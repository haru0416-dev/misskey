# 開発エージェント運用仕様

作成日: 2026-09-08
状態: 利用者の置換指示に基づき、運用文書と生成入口へ適用。実セッションでの読込監査と性能・品質・費用の比較評価は未実施。

## 位置付け

このプロジェクトの要求、実装上の制約、作業中に確認した問題を基に、開発エージェントの判断と検証を定義する。外部製品の導入仕様、翻訳、短縮版、互換実装ではない。外部の文面・例・人格設定・モード名・固有の手順構成は移植しない。

本書は指示体系の設計仕様。実際に読む共通規則は [AGENTS.md](../AGENTS.md)、作業別の手順は `.claude/skills/` に置く。本書の全文を常時注入しない。第三者由来の表現を残す場合は必要な著作権・ライセンス表記を保持する。元の表現を実質的に残さず独自に書き直した本文には、旧本文の帰属を引き継がせない。

[内部最適化計画](optimization-plan.md)の実装開始前に、本仕様に沿って運用規則を整理し、適用経路と検証方法を確認する。

## 達成する状態

要求された挙動を維持したまま、性能、保守運用、機能追加に伴う負担を減らす。コード量、応答文の短さ、ツール実行回数のいずれも単独の目的にしない。

変更案は次の順で判断する。

| 判断 | 採用条件 |
| --- | --- |
| 要求充足 | 指定された機能・調査範囲・成果物が揃う。簡単な別問題への置換や無断の範囲縮小がない |
| 保護する契約 | 認証、公開範囲、データ整合性、連合互換性、既存テストの検出能力が維持される |
| 継続して変更できる構造 | データ・資源・副作用の所有者と変更の波及先が追える。不要な二重実装を残さない |
| 負荷と作業量 | 必要な契約を満たす候補間で、実測した処理負荷と継続的な保守対象を比較する |

上位の条件を満たさない候補を、下位の改善で採用しない。構造整理だけでは高速化を主張しない。

## 変更前に確定すること

要求と関連コードから、次の三点を特定する。単純な修正で毎回書式付きの計画を提出する必要はない。複数の境界を変更する場合は作業記録に残す。

- **利用側の結果**: 誰が何を観測できれば完了か。許可される結果だけでなく、起こしてはいけない副作用も含める。
- **変更の境界**: 入力、認可、保存、非同期処理、応答のうち、どこを変えるか。同じ処理を使う別経路は何か。
- **確認方法**: 既存テスト、実行シナリオ、出力差分、負荷計測のどれで契約を確認するか。

仕様判断は、現在のコード・設定・テスト・実行結果に照合する。説明文だけを根拠に実装を変更しない。矛盾した規則は黙って無視せず、矛盾箇所と影響を明らかにして正本の修正につなげる。

利用者が報告した失敗や制約は作業の前提とする。確認のためだけに同じ失敗を再実行せず、原因の切り分けや修正確認に必要な観測を選ぶ。

## 実装の判断

### 再利用と変更範囲

既存の実装を再利用するかは、入力、認可、保存形式、失敗時の扱いが要求に合うかで決める。似た名前や短い呼び出しだけでは選ばない。標準機能や導入済みライブラリも同じ条件で評価する。

共通処理の不具合は、その処理と利用経路を調べて直す。個別の入口だけに回避処理を足し、他の利用側に同じ不具合を残す修正は完了としない。逆に、局所の問題を根拠なく全体の抽象化へ広げない。

必要な境界を表す型、factory、別ファイルは、利用数が一つでも存在理由になり得る。削除・統合は行数ではなく、依存関係や資源所有を曖昧にしないかで判断する。

### 内部互換の廃止

内部 API、型、配置、設定は必要に応じて破壊的に変更できる。全利用箇所を移し、移行完了時に旧 export、alias、分岐、不要依存を削除する。二重実装を恒久的な逃げ道にしない。

旧互換が不要であることは、既存データの削除、migration 履歴の改変、外部への送信、認証情報の利用を許可するものではない。これらは別の権限と安全条件に従う。

### エラーと非同期処理

処理の受理、DB 保存、queue 投入、相手での反映を区別する。成功応答や完了記録が何を保証するかを定め、それより強い保証を報告しない。

非同期化や並列化では、所有者、同時実行上限、待機上限、キャンセル、再実行、終了時の扱いを確認する。応答を早める代わりに未完了処理を無制限に増やさない。

fallback は成立条件と結果の意味を持つ場合だけ使う。失敗を握りつぶして成功扱いにする代替動作は設けない。恒久的な外部副作用については、再配送と冪等な最終状態を検証し、exactly-once を仮定しない。

## このリポジトリで保護する境界

| 境界 | 確認する内容 |
| --- | --- |
| 認証・認可 | token scope、利用者・役割、停止・ブロック、HTTP と streaming の権限が維持される |
| 公開範囲 | 投稿の配送先だけでなく、取得 API、ActivityPub 取得、cache、WebSocket からも未許可の情報を出さない |
| 投稿と予約投稿 | note・集計・outbox の原子性、draft のロック・再検証・投稿・削除の原子性を維持する |
| 連合 | actor/object の識別、署名、宛先、Follow/Undo/Delete/Move 等の意味と、指定 upstream との双方向動作を維持する |
| 外部接続 | URL・接続先・redirect・署名者の検証を、再利用や高速化の都合で省略しない |
| DB と migration | transaction、接続予算、セッションロック、journal、失敗時の解放を維持する |
| ブラウザ状態 | アカウント間の分離、保存と復元、非同期取得の取消、購読と timer の解放を維持する |
| 操作面 | 入力・表示・keyboard・フォーカス・スクロール等、実際の利用経路を確認する |

これらを全作業で同じ量だけ調査するのではなく、変更する境界とその利用側に適用する。新しい保護条件が判明した場合は、この表の追記だけで終わらせず、対応する検証も決める。

## 検証と報告

既存テストは、守る挙動と検出できる回帰を維持する。内部構造に依存する assertion は、利用側から観測できる契約へ移す。期待値の変更、skip、対象の縮小で失敗を隠さない。

恒久テストを追加するのは、現実的な不具合を検出でき、今後も保持する意味がある場合。単にテストの数を揃えるためには増やさない。確認だけに使う一時コードは、結果を記録してから除去する。

| 変更 | 完了の証拠 |
| --- | --- |
| 不具合修正 | 報告された失敗を対象にした修正確認。可能なら修正前に失敗する回帰テスト |
| API・DB・queue | 利用側の結果、保存された状態、失敗・競合・再実行時の副作用 |
| HTTP・WebSocket・連合 | 実際の通信境界を通る結果。関数単体の成功だけで代用しない |
| UI | 実ブラウザで対象操作を行った結果。型検査だけで表示・操作の正常性を主張しない |
| 性能 | 同条件の複数回比較と、本文・順序・権限・副作用を別に確認した結果 |
| 文書・設定 | 参照先、コマンド・設定の現行実装との整合。文章を変更しただけで挙動改善を主張しない |

性能比較では実ランタイム、開始 revision、データ状態、負荷、観測範囲を固定する。失敗した候補を欠測として除外しない。平均値や SQL 本数だけで判断せず、遅延の裾、非同期完了、資源上限も対象にする。

完了報告には成果物、確認したこと、未確認・残存リスクを必要なだけ書く。短文化のために失敗や制約を落とさず、求められた説明・分析は省略しない。チェックリストの自己申告を実行証拠の代わりにしない。

## 指示の配置と正本

同じ規範を複数箇所で独立編集しない。内容ごとの正本と、それを読む入口を分ける。

| 配置先 | 役割 | 置かないもの |
| --- | --- | --- |
| AGENTS.md | このプロジェクトの目的、常時必要な契約、参照先 | 手順書の全文、モデル依存の未検証説、長い履歴 |
| 各 harness の入口 | 正本を確実に渡すための薄い接続 | 別系統の規則、独自の安全性例外 |
| 作業別 Skill・参照文書 | 特定の変更で必要な判断、現行手順、関連実装と検証への参照 | 一般論の再掲、無関係な作業への常時注入 |
| package scripts・検査コード・CI | 再現可能なコマンドと機械判定 | 未実行なのに通過扱いになる自己申告 |
| 計画・調査記録 | 変更理由、検証条件、未解決事項 | 現行仕様と見分けられない過去の手順 |

参照できない harness 向けに再掲が必要なら、生成または整合検査で正本との一致を保つ。具体的な方式は実装時に選び、同じ手順をさらに別の文書へ手書きで増やさない。

作業別 Skill の説明は、必要になる操作と対象を表す。発火語を増やすこと自体を目的にしない。利用者の明示呼び出し、対象操作に応じた参照、harness の読込のうち、どの経路で適用するかを決める。

配置済みと適用済みを区別する。評価時には実際に渡された本文を記録する。harness 固有の hook、状態保存、全 subagent への注入は必要性を確認してから実装し、別プロジェクトや別セッションの設定へ暗黙に波及させない。

## 規則を更新する条件

既存の規則は、次のいずれかに分類して移行する。

- **維持**: 現在も成立する契約で、編集時の判断に必要。
- **修正**: 目的は必要だが、対象ファイル、コマンド、前提、適用範囲が現行と異なる。
- **移管**: 必要な時だけ読む手順、機械検査、または履歴へ置く方が役割に合う。
- **削除**: 目的を失った規則、同じ条件の重複、実装や検証を伴わず行動だけを増やす規則。

規則を残す際は、対象となる契約、現在の実装または失敗記録、確認方法を対応させる。モデルやツールの特定版で観測した挙動は、その条件を付ける。普遍的な禁止へ拡張しない。

新しい規則は、文面の説得力だけで採用しない。利用者が指定した方針は方針として明記し、実験で効果が示されたという主張とは分ける。安全条件の機械化が未完了の間は、その条件を削除しない。

## 効果を確認する評価仕様

本仕様の性能・品質への効果は未測定。利用者の指示による運用文書の置換と、効果の実証を分ける。以下の比較を行うまでは改善を主張せず、文書整合や lint の成功をその代わりにしない。

比較条件:

- 置換前の指示体系。評価開始時に比較元 revision を固定して復元する。
- 現行の契約を保ち、古い記述と重複を整理した体系。
- 整理済みの体系に、本仕様の判断基準を適用した体系。

モデル、harness、開始 revision、権限、データ、ツール、共通の安全条件を揃え、独立した作業環境と新しいセッションで実行する。今回の会話や他条件の指示が混入していないかを確認する。費用・時間の比較時は共有資源への負荷も揃える。

評価課題は本番コードを無断で変更せず、隔離環境で行う。初期の対象は次の通り。

| 課題 | 観測する失敗 |
| --- | --- |
| 共通の投稿処理の修正 | REST だけ直し AP・予約投稿を壊す、transaction を分断する |
| 内部 API の切り替え | 呼び出し元の移行漏れ、旧 alias の残存、生成型との不一致 |
| timeline の取得・描画変更 | 投稿の欠落・重複・順序変更、未許可情報の表示、購読の残存 |
| queue の遅延・再実行 | 二重副作用、回復不能、無制限の滞留、正常終了時の取りこぼし |
| migration の変更 | 意図しないデータ削除、履歴改変、セッションロックの喪失 |
| 小さな UI または文書変更 | 不要な全体再設計、依存追加、無関係な手順の大量実行 |

合否は要求充足と保護する契約から先に決める。後から文面に都合のよい課題だけを残さない。評価専用の確認は候補エージェントによる変更対象から外す。

各条件を複数回実行し、失敗・未完了・除外理由を保存する。少数課題での予備評価と一般的な改善の証明を区別する。調整に使っていない課題でも確認する。比較するのは結果と実行記録であり、特定の文言への従順さではない。

## 適用と効果確認の完了条件

- 規則ごとの移行先と保持・修正・移管・削除の理由が整理されている。
- 常駐情報、作業別情報、機械検査の責務が分かれ、各入口が同じ契約を渡す。
- 新しい構成に実際に届く指示と、既存の上位指示との整合が確認されている。
- 効果を確認する際は、要求省略、回帰、公開範囲違反、データ破損を許容しない評価を通す。未実行を通過扱いにしない。
- 不要になった旧規則・入口・依存を除去している。既存ファイルに必要なライセンス情報は保持している。
- 効果を確認した条件と、未検証の範囲を記録している。

## 適用先と検証の分担

| 変更対象 | 適用内容 |
| --- | --- |
| AGENTS.md | 共通の判断、保護する契約、編集・外部操作の制約と作業別の入口を正本化 |
| CLAUDE.md / Copilot / Codex | Claude は正本の import、Copilot は正本の生成コピー、Codex Skills は同じ name/description と正本への参照 |
| backend / frontend Skills と参照 | 現行の実装・設定・テストに照合し、固有の判断と検証先へ整理 |
| shipping / 起票 / context 調査 | 変更境界に応じた検証、送信承認、観測と推定の区別を維持 |
| reviewers / commands / README | 正本の派生チェックリストや主観的な点数を廃止し、対象と証拠を渡す入口へ整理 |
| 生成・検査 | `bun run sync:agent-instructions` で入口を更新。`bun run lint:agent-instructions` が不一致を拒否し、全体 lint と CI から実行 |

`scripts/sync-agent-instructions.test.mjs` は、生成先の独立編集を検出し、検査だけでは書き換えないことと、不正な正本の metadata で生成先を更新しないことを確認する。これは入口ファイルの契約の検証であり、モデルの判断改善を測る試験ではない。

リポジトリの `.claude/settings.json` は削除する。個人・グローバルの設定や指示、起動中セッションに注入済みの内容は変更しない。リポジトリ設定の削除だけで全プラグインが無効になるとはみなさず、新しいセッションでどの本文が渡されるかは harness ごとに確認する。
