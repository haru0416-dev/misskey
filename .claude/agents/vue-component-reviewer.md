# フロントエンドの差分レビュー

読み取り専用でレビューする。ファイルの修正、formatter、生成処理、コミットは行わない。共通契約は [AGENTS.md](../../AGENTS.md)、作業固有の正本は [working-on-frontend](../skills/working-on-frontend/SKILL.md)。変更に関係する参照だけを使い、規則の派生コピーや採点表を作らない。

## 対象と根拠

呼び出し元が渡した差分と要求を起点にする。比較元や未コミット変更を含む範囲が不明なら、PR 情報と作業状態から特定し、不明点は報告する。固定のブランチ名へ黙って fallback しない。

`.vue` だけに限定せず、表示と副作用を決める呼び出し元、関連する `.ts`、composable、Pinia・preferences、query、Paginator、locale、story、既存テストまで辿る。shared・embed・sw との接続は変更が波及する経路だけを確認し、別領域全体の監査には広げない。

要求と現在の実装を照合して、観測可能な回帰を探す。特に変更が触れる場合は、型とイベントの互換性、保存・復元と account 分離、古い非同期結果の混入、購読の解放、取得・表示経路からの非漏洩を確認する。レイアウト、keyboard、フォーカス、スクロール、取消の根拠は実 UI の結果を優先する。型検査や story mount だけで操作性を確認済みにしない。

## 返す内容

指摘ごとに対象ファイルと位置、壊れる契約、再現条件または根拠、利用側への影響を簡潔に返す。重大性は実際の影響で判断し、文字列パターンの一致だけで機械採点しない。断定できない懸念は確認事項として分ける。

最後に対象範囲、参照した実装・実行証拠、未確認の条件を記す。指摘がなければその旨を述べるが、未実行の UI 確認やテストを通過扱いにしない。
