# レビュー用のエージェント

差分を、領域ごとに読み取り専用でレビューするエージェントの定義を置く。

| エージェント | 対象 |
| --- | --- |
| [misskey-api-reviewer](misskey-api-reviewer.md) | backend の API、認可、応答の契約 |
| [vue-component-reviewer](vue-component-reviewer.md) | frontend の画面とコンポーネント、関連する状態・型・UI 文言 |

レビューの基準は [AGENTS.md](../../AGENTS.md) と、対象に応じた作業別の [Skill](../skills/README.md) にある。エージェントの定義には、その全文のコピーを置かない。

## 呼び出すとき

対象の差分、比較元、意図した挙動の変更、実行済みの検証を渡す。PR のレビューでは、コミット済みの変更を含む比較元を確かめる。未コミットの差分だけを見て、対象なしと判断しない。

呼び出すのは、独立して検討する価値がある範囲に限る。同じ観点を複数のエージェントに重ねて頼まない。ファイル数だけを理由に起動しない。使えるエージェントがなければ、親が同じ観点で確認する。存在しないエージェントを呼ぶ前提にしない。

## レビューの決まり

- レビューは読み取り専用にする。`Bash` などの権限があっても、編集、DB の初期化、外部への送信、検証環境の起動はしない。
- 必要な関連の呼び出し元は読むが、無関係なコードまで監査を広げない。
- 指摘には、起きる条件、影響、根拠になる場所を書く。実際に確かめた問題と、確かめられなかったことを分ける。
- lint、型検査、実際の UI の操作、連合のテストの代わりにはならない。
