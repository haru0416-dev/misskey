# CHANGELOG の追記先

追記が必要な条件と書式は [AGENTS.md](../../../../../AGENTS.md) を正本とする。ここでは [CHANGELOG.md](../../../../../CHANGELOG.md) の編集箇所を確認する。

- 現在の `## Unreleased` の利用者への影響に合う箇所へ追記する。共通・横断的な変更は `### General`、クライアントは `### Client`、サーバーは `### Server` を使う。
- 既存エントリは並べ替えない。空欄の `-` だけがある場合はそれを置き換える。過去のリリース本文は変更しない。
- `### Note` に更新時の注意が置かれている場合は保持する。設定や互換性の変更で注意書きが必要なら、利用者に必要な対応を実際の変更に合わせて記載する。
- 記述するのは利用者が観測する機能・修正・必要な操作であり、実装手順の列挙や未測定の改善率ではない。
- 内部規則・文書整理だけで利用者の動作が変わらない場合は、その理由を完了報告に残し、機能改善のエントリを作らない。

隣接エントリの書き方に合わせつつ、要求された変更が過不足なく表されていることを確認する。脆弱性の非公開情報は [SECURITY.md](../../../../../SECURITY.md) に従い、公開前の詳細を CHANGELOG へ移さない。
